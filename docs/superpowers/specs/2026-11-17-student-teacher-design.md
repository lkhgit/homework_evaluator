# 학생용·선생님용 분리 설계

## 목적과 결정

본 프로젝트는 homework_evaluator_friend이다. 첫 화면에서 학생용과 선생님용을 선택한다. 사용자는 공통 분석 결과를 두 화면에서 활용하는 방식 대신, 학생·교사 기능을 각각 구현하는 방식을 선택했다.

학생용은 원래 과제의 요구사항을 보존하면서 실행 순서를 안내한다. 선생님용은 기존 접근성 분석·개선 흐름을 유지하고 반복 수정과 복원을 추가한다. 자료 읽기 같은 기술 함수는 재사용할 수 있지만 두 모드의 분석 결과 형식, 프롬프트, API, 화면 상태는 독립적으로 관리한다. 로그인이나 권한 구분을 의미하는 역할 선택은 아니다.

## 현재 구조와 변경 범위

현재 src/app/page.tsx가 교사용 전체 흐름을 소유한다. src/lib/pdfText.ts는 브라우저에서 PDF 텍스트만 추출하고 페이지별 출처를 결과에 보존하지 않는다. 기존 OpenAI API는 objective, analyze, repair, preview로 구성된다. 학생용 HTML은 교사가 수정한 과제와 분석 단계에서 생성된다.

현재 교사용 화면 흐름을 /teacher로 이동하고 /에는 역할 선택을 둔다. /student는 별도의 학생용 흐름으로 만든다. 기존 교사용 API 계약은 유지하고 학생용 분석·참고 검색·교사용 대화 수정은 별도 경로에 둔다. 기존 엔진·수정 제안·학생용 HTML 내보내기는 계속 지원한다.

영향 범위: 첫 화면과 내비게이션, 두 모드의 자료 입력 UI, PDF·이미지 읽기, 출처 모델, 각 API의 요청 검증, 학생 분석과 단계 안내, 교사 수정·이력, 참고 검색, 관련 테스트와 실행 안내. API 키는 서버에만 둔다.

## 입력과 출처

두 모드 모두 여러 PDF, PNG/JPEG 이미지와 추가 글을 함께 받아 하나의 과제로 처리한다. 다른 문서 형식은 이번 범위에 포함하지 않는다. 원본은 수정하지 않으며 문서 ID, 파일명, PDF 페이지, 텍스트 구간 또는 이미지 참조를 보존한다.

PDF는 텍스트와 페이지 이미지를 함께 활용한다. 이미지 입력을 지원하는 모델 호출로 표·그래프·그림과 스캔 PDF를 읽는다. 텍스트 추출 실패를 빈 문서로 처리하지 않는다. 판독 불가·불확실한 수치와 단위는 확인이 필요한 상태로 표시한다. 이미지에서 읽은 설명은 원문 텍스트 인용과 구별한다.

파일 형식, 실제 파싱 가능 여부, 개별·전체 용량, 페이지 수, 글 길이에 상한을 두고 클라이언트와 서버에서 검증한다. 상한을 넘으면 누락 없이 알리고 조정을 요청한다. 구체적 상한은 구현 시 기존 요청 한도와 모델 입력 예산에 맞춰 정한다. 원본 페이지는 필요한 때 렌더링하며 사용하지 않는 PDF·Blob 자원은 해제한다.

## 충돌

충돌이 없으면 빈 충돌 칸을 만들지 않는다. 제출 조건·수량·단위·절차 등 실제 충돌이 발견될 때만 눈에 띄는 경고와 양쪽 출처를 표시한다. 충돌 알림은 키보드·스크린리더로도 확인할 수 있어야 한다.

AI는 충돌 조건을 임의로 선택하지 않는다. 교사는 적용 조건을 지정할 수 있다. 학생은 교사 확인이 필요한 충돌을 명확히 보며, 해결되지 않은 조건이 확정된 안내로 표현되지 않아야 한다. 영향을 받지 않는 단계는 확인할 수 있다.

## 학생용

자료 입력 → 분석 → 단계별 수행 안내 → 제출 전 점검 순서이다. 학습 목표 확정이나 접근성 개선안 채택을 학생에게 요구하지 않는다. 답안 작성이나 과제 조건 변경은 하지 않는다.

각 단계는 다음 항목을 항상 갖는다.

- 지금 할 일
- 준비물·도구
- 완료 확인 기준
- 반드시 기록하거나 기억해야 할 내용·주의사항
- 관련 원문·수행 조건
- 필요한 경우 펼쳐보는 원본 그림·표·그래프

내용이 없으면 없음 또는 지침에 명시되지 않음으로 표시한다. 판독 실패·정보 부족은 없음과 구별한다. 원문에 없는 완료 기준을 제안하는 경우 AI의 보조 기준임을 표시한다. 관련 원문·수행 조건은 단계별로 제공하되 평가 기준 목록은 반복하지 않는다.

학습 과제의 필수 활동, 수치·단위·절차, 제출 요구사항과 안전 지침을 보존한다. 위험한 실험 지침을 추측해서 보완하거나 외부 자료로 원래 조건을 대체하지 않는다. 각 필수 요구사항을 단계 또는 제출 점검 항목에 연결하고, 연결하지 못한 조건은 경고한다. 이는 내용의 완전성 보장이 아닌 누락 점검이다.

원본 시각 자료는 버튼으로 펼쳐 보고 파일명·페이지를 확인한다. 정확한 그림 분리가 어려우면 해당 페이지 전체를 보여준다. 읽을 수 없는 정보는 원본 확인을 요청한다.

### 제출 전 점검

지침에 명시된 평가 기준이 있으면 우선 표시하고 AI가 제안한 추가 점검 항목을 덧붙인다. 없으면 AI가 점검 항목을 생성한다. 두 종류는 출처와 라벨로 구별한다. AI 제안은 실제 교사의 채점 기준이나 배점을 의미하지 않는다. 평가 기준은 이 화면에 한 번 모아서 제시한다.

### 용어와 참고 자료

AI가 필요하다고 판단한 용어에만 짧은 뜻을 붙인다. 마우스 올리기, 클릭, 터치, 키보드로 열고 닫을 수 있게 하며 기본 화면 공간을 차지하지 않는다. 단계별 의무 개수는 없다.

참고 자료는 학생이 단계의 버튼을 눌렀을 때만 실제 외부 검색을 실행한다. 설명·블로그·서적 정보를 간결하게 제공하며 왜 도움이 되는지 문구는 넣지 않는다. 검색으로 확인한 출처와 링크만 제공하고 서적은 확인된 저자·제목과 확인 페이지를 제시한다. 검색 실패·결과 없음은 명시한다. 실제 검색 도구가 연결되지 않으면 모델 기억으로 링크를 만들어내지 않는다.

검색은 서버에서 실행하고 키를 브라우저에 노출하지 않는다. 전체 파일 대신 해당 단계와 필요한 주제만 검색 질의에 사용한다. 외부 콘텐츠와 업로드 자료의 명령을 시스템 지시로 실행하지 않는다. 같은 단계의 같은 분석 버전에서 검색한 결과는 재사용하고 단계가 바뀌면 이전 결과를 잘못 붙이지 않는다.

## 선생님용

기존 학습 목표 확인, 활동 분석, 접근성 문제, 개선안 검토, 조건 검증, 미리보기와 내보내기를 유지한다. 다중 자료와 시각 자료도 분석에 포함한다.

AI가 어려운 단계, 빠진 중간 과정, 충돌하는 평가 기준을 출처와 함께 제시한다. 교사는 해당 문제에 의견을 입력하고 수정안을 받는다. 적용 전 변경 내용을 확인하며, 선택한 수정이 과제 내용과 관련 분석에 반영된다. 적용하지 않은 제안은 현재 과제를 바꾸지 않는다. 수정된 지침을 재분석하고 아직 해결하지 못한 문제는 남긴다.

### 변경 이력

최초 분석과 적용 완료한 수정마다 1, 2, 3 형태로 버전을 저장한다. 별도 이력 창에서 짧은 변경 설명을 보고 버전을 선택해 내용을 확인한 후 복원한다. 임시 입력·실패한 요청은 버전으로 남기지 않는다.

각 버전은 과제 내용, 학습 목표, 분석, 적용한 개선과 미리보기 등 일관된 전체 상태를 보존한다. 복원은 새 버전으로 기록해 이후 이력도 유지한다. 복원 시 이전 요청의 늦은 응답이 현재 상태를 덮어쓰지 않는다. 변경한 과제와 오래된 분석을 섞어 표시하지 않는다.

이번 범위에서는 계정·클라우드 저장소를 추가하지 않는다. 이력과 원본 파일은 브라우저 IndexedDB에 과제별로 보존하고 저장 실패를 알린다. 저장된 자료를 삭제하는 동작을 제공한다. 브라우저 데이터 삭제 시 소실되며 다른 기기와 공유되지 않음을 안내한다. 이것은 구현 제안으로 설계 승인 대상이다.

## 구현 원칙과 검증

현재 설치된 Next.js 문서를 읽고 라우트·서버 요청 구현에 적용한다. 기존 OpenAI 연결을 사용하되 이미지 분석과 실제 검색 지원은 설치된 SDK 및 공식 문서에서 확인한다. 원본 이미지 입력과 외부 검색은 추가 API 비용·지연이 발생할 수 있다. 모델명·검색 옵션은 확인 후 계획에 명시한다.

검증은 다중 자료 출처, 실제 충돌 시에만 경고, 스캔 PDF·표·그래프 판독 실패 처리, 학생 단계 필수 필드·요구사항 보존, 평가 기준 라벨, 버튼 클릭 전 검색 없음, 검색 결과 출처, 이력 복원과 늦은 응답 차단을 포함한다. 기존 테스트와 타입·린트·빌드 및 학생/교사 기본 흐름의 브라우저 확인을 수행한다. 실제 모델 호출과 모의 응답 검증은 결과에서 구별한다.

## 제외 범위

계정, 권한, 과제 공유, 교사·학생 간 자동 전달, 자동 채점, 학생 답안 생성, 실시간 협업, 이미지 영역 자동 정밀 분할은 포함하지 않는다. 기존 PDF 텍스트만으로 접근성 근거를 검증하던 기능을 이미지까지 정확히 검증한다고 주장하지 않는다.
