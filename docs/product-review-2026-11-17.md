# 첫 사용자 관점의 제품 점검

점검일: 2026-11-17. 실제 소스, 로컬 화면, 자동 브라우저 검사를 대조했다. 사용성 테스트 참가자를 모집한 조사는 아니다. 학교 또는 공개 서비스 운영 여부는 아직 확인되지 않았으므로 공개 운영 관련 항목은 조건부 권고다.

## 이번에 수정한 내용

- 정보 라벨의 파란 칩 배경을 제거했다. 항목명은 굵은 글씨로, 버튼은 테두리와 호버 반응으로 구분한다.
- 순서도 카드에 ‘상세 보기’와 ‘선택한 단계’를 표시했다. 클릭할 이유와 선택 상태를 글자로 알린다.
- 펼침 영역에 명확한 테두리를 부여했다. 키보드 초점은 기존 규칙을 유지한다.
- 돌아갈 수 있는 교사용 진행 단계만 버튼 테두리를 표시한다. 아직 열리지 않은 단계는 일반 정보 표시로 남긴다.
- 개선안의 적용/유지 선택에 aria-pressed를 추가했다. 선택 상태는 색과 접근성 속성으로 함께 표현한다.
- 이력 삭제는 붉은 테두리와 ‘이력만 삭제’라는 문구로 구별했다. 확인 절차는 유지한다.
- 입력 버튼 근처에 외부 AI 전송 안내와 자료 처리 안내 링크를 추가했다.
- 공통 헤더와 하단에 실제로 열리는 이용 안내 경로 `/guide`를 연결했다.
- OpenAI Responses 호출 모두에 `store: false`를 명시했다. 이는 응답 상태 저장 설정이며 제공사의 모든 로그 삭제나 무보관을 보장하지 않는다.

## 공개 운영 전 우선 확인

### 1. 정식 개인정보처리방침은 아직 없다

`src/app/guide/page.tsx`는 현재 구현을 설명하는 이용 안내다. 운영자 상호/이름, 개인정보 담당자 연락처, 실제 호스팅과 로그 보관, 처리 목적과 법적 근거, 보유기간, 권리 행사, 국외이전 근거와 조건이 확정되지 않았다. 이를 임의로 채워 정식 방침처럼 공개하면 사실과 다른 약속이 된다.

권고: 운영 범위와 실제 사업 주체를 먼저 확정하고, 개인정보를 처리하는 방식에 맞는 방침을 작성한다. 해외 AI 제공사 및 호스팅 계약과 학교 내부 정책도 확인한다. 이용약관에는 서비스 역할, 금지 자료, 결과 책임과 한계, 중단과 변경, 문의 절차를 정한다. 약관 링크 자체가 모든 법적 요건을 충족시키지는 않는다.

근거: 개인정보 포털의 개인정보 처리방침 작성지침과 국외이전 제도 안내.

### 2. ‘로컬 저장’은 개인정보 보호 약속이 아니다

`src/lib/browserStore.ts`의 IndexedDB에 파일과 결과를 저장한다. `src/app/student/page.tsx:32`는 이전 결과를 자동 복원한다. 공용 PC의 동일한 브라우저 프로필이면 다음 사용자가 내용을 볼 수 있다. 별도 로그인이나 잠금은 없다.

권고: 자동 저장 끄기 또는 공용 컴퓨터 모드, ‘이 기기의 모든 자료 삭제’를 우선 설계한다. 삭제 전에 학생용 자료, 교사용 이력, 원본 파일을 따로 집계하고 실제 삭제 범위를 설명해야 한다. 현재 과제 초기화는 전체 사이트 저장 공간 삭제와 다르다.

### 3. 이력 삭제와 원본 삭제가 분리되어 있다

`src/components/TeacherHistory.tsx:48`은 프로젝트 이력만 제거한다. 첨부 파일은 `teacher-files:<projectId>`라는 별도 키에 저장한다. 원본 파일은 이력과 별개로 남을 수 있다.

권고: ‘이력만 삭제’와 ‘과제와 원본 모두 삭제’를 별도 동작으로 구분하고, 전체 삭제는 확인 후 처리한다. 초기 버전에서는 전체 삭제 버튼 하나보다 삭제 범위가 정확한 동작이 우선이다.

### 4. 공개 익명 API에 대한 비용 통제가 충분하지 않다

`src/lib/rateLimit.ts:15`의 제한 상태는 서버 프로세스의 메모리 Map에 있다. 서버 재시작과 여러 인스턴스 사이에서 공유되지 않는다. 주석도 로컬 데모용 제한임을 명시한다. 로그인 기반 사용자 한도는 없다.

권고: 외부 공개 시 서버 단위 공유 제한, 비용 상한, 운영 알림, 필요하다면 인증을 도입한다. 개인용 로컬 도구라면 로그인부터 추가할 이유는 약하다.

### 5. 취소와 비용 취소는 다르다

`src/components/TeacherApp.tsx:194`의 요청 식별자는 늦은 응답이 화면을 바꾸지 못하게 한다. 서버와 외부 AI 작업이 반드시 중단된다는 뜻은 아니다.

권고: 화면 취소와 서버 처리 중단을 구분한다. 중복 요청 방지와 요청 취소 신호 전달을 설계하되, 이미 시작한 외부 요청의 과금 회수를 약속하지 않는다.

## 실제 사용성을 크게 개선할 항목

### 6. 접근성 ‘통과’ 표현은 과도하다

`src/components/WorkflowScreens.tsx:705` 등의 판정은 추출한 요구 수준과 자체 엔진 규칙을 사용한다. 실제 과제를 보조공학으로 실행하거나 웹 페이지의 키보드 접근성을 시험한 결과가 아니다. 같은 파일의 ‘통과/실패’ 표시는 이 차이를 충분히 설명하지 않는다.

권고: ‘예상 부담 낮음/추가 확인 필요’ 같은 표현과 판단 근거를 함께 제시한다. 학생의 능력 판정이나 공식 접근성 인증처럼 보이지 않게 한다. 결과 계산 기준을 바꾸는 일과 화면 문구를 바꾸는 일은 구별해 검토한다.

### 7. 교사용은 긴 과정을 끝내야 결과를 쓸 수 있다

교사용은 목표 확인, 분석, 어려움, 개선안, 접근 조건, 수정본을 차례로 거친다. 이미 잘 작성된 과제를 빠르게 점검하려는 교사는 어디까지 해야 하는지 어렵다.

권고: ‘원본 그대로 점검 마치기’, ‘선택한 개선안으로 수정본 만들기’를 명확히 구분한다. 단계를 무조건 늘리거나 버튼을 여러 개 추가하는 것보다 사용 목적에 맞는 종료 경로가 중요하다.

### 8. 파일을 여러 번 읽는 구조가 대기와 비용을 늘린다

`src/components/TeacherApp.tsx:215`부터 추출, 목표 도출, 본 분석, 충돌 검사에서 같은 원본이 여러 요청에 사용된다. 본 분석도 여러 모델 호출을 수행한다.

권고: 실제 요청 수, 파일 크기별 대기시간, 오류율과 비용부터 측정한다. 그 결과를 근거로 시각 입력을 공유할 수 있는 구간을 통합한다. 측정 없이 ‘몇 초 만에 완료’ 같은 문구를 넣지 않는다.

### 9. 안전 지시와 수치는 일반 경고와 중요도가 다르다

현재 경고를 닫을 수 있지만, 반응 시간 충돌이나 용액 농도 불일치는 실험 안전 및 결과에 직접 영향을 준다. 원문 인용 검증에 실패한 근거도 있다.

권고: 안전/수치/제출 조건에 영향을 주는 경고에는 해당 단계와 원본 페이지로 이동하는 링크를 제공한다. 닫기는 시각적으로 숨기는 동작이며 ‘해결됨’이 아님을 구별한다. 원문을 읽지 못한 상태를 정상 완료처럼 표시하지 않아야 한다.

### 10. 학생용에는 실제 수행을 기록하는 도구가 없다

`src/app/student/page.tsx`는 선택한 단계만 바꾼다. ‘완료한 단계’ 상태나 이어서 할 단계 저장은 없다.

권고: ‘이 단계 완료’와 완료 취소, 최근 진행 단계 복원을 우선 검토한다. 선택한 단계와 완료한 단계를 같은 파란색으로 표현하면 안 된다. 교사에게 제출되었다는 의미도 부여하지 않는다.

### 11. 학생용 안내를 가져갈 방법이 부족하다

교사용은 HTML을 내려받지만, 학생용에는 안내 인쇄/내려받기 동작이 없다. 기기를 바꾸거나 실험실에서 인터넷 없이 확인하기 어렵다.

권고: 먼저 인쇄와 PDF 저장에 맞는 출력 화면, 텍스트 복사를 제공한다. 계정과 클라우드 공유는 실제 동기화 수요가 확인된 다음 결정한다. 공유 링크를 만들면 접근 권한, 만료, 삭제, 개인정보 노출 문제까지 함께 설계해야 한다.

### 12. 참고 자료의 신뢰도와 외부 이동이 충분히 드러나지 않는다

`src/app/api/references/route.ts:12`는 웹 검색 인용 URL을 추려 돌려준다. 링크 목록은 자동 검색 결과이며 원래 과제 지침이나 교사가 승인한 자료와 동일하지 않다.

권고: 원문 출처와 외부 참고 자료를 구분하고, 출처 기관/도메인과 새 창 이동 여부를 표시한다. 최신성이나 정확성을 확인하지 않고 ‘추천 자료’라고 단정하지 않는다.

### 13. 예시가 한국어 사용 맥락과 다르다

교사용 예시는 영어 생명과학 과제다. 한국어 사용자에게는 기능을 배우기 전에 영어 예시와 낯선 학습 플랫폼을 이해해야 하는 부담이 생긴다.

권고: 한국어 예시를 하나 추가하되 원문, 분석 근거, 개선안, 테스트 데이터까지 함께 준비한다. 화면 문구만 번역해 데이터와 불일치시키면 안 된다. 실제 수업 자료는 개인정보와 배포 권한을 정리한 뒤 사용한다.

### 14. 운영자가 받는 문제 신고 경로가 없다

파일 판독 오류, 안전 수치 오류, 삭제 요청을 보낼 연락처가 정해져 있지 않다.

권고: 운영자 연락처가 확정되면 ‘문제 신고’를 연결한다. 원본 파일을 자동 첨부하지 않고 사용자가 선택하게 하며, 보고 내용과 개인정보 수집 범위를 설명한다. 작동하지 않는 문의 버튼은 만들지 않는다.

## 지금 추가하지 않는 편이 좋은 것

- 분석과 무관한 대시보드, 사용량 그래프, 배지와 점수판.
- 실제 진행률이 없는 퍼센트 표시.
- 역할 선택을 권한 관리처럼 포장한 로그인 화면.
- 도입하지 않은 광고/분석 쿠키 때문에 띄우는 형식적 동의 배너.
- 이름과 연락처도 정하지 않은 운영자 정보와 가짜 개인정보처리방침.
- 아직 서버 동기화가 없는 상태에서 ‘클라우드 저장 완료’라는 표시.

## 검증과 한계

Hallmark 앱 범위 검사에서 4개 경로의 렌더링을 확인했다. 14개 화면 상태를 1440, 1024, 768, 390px에서 검사했고 주요 접근성 오류는 없었다. 자료 복원, 오류 시 입력 보존, 취소 후 늦은 응답 무시, HTML 내려받기와 개선안 없는 과제의 이동을 확인했다. 단위 테스트, 타입 검사, 프로덕션 빌드가 통과했다.

AI 응답은 고정 데이터로 대체했다. 실제 학생/교사 사용자 조사, 실험 안전성 검증, 휴대폰 실기기 검사, 호스팅 계정과 개인정보 계약 검토는 포함하지 않았다. 10분 정도의 소스 및 화면 점검은 사용자 조사와 법률 검토를 대신하지 않는다.
